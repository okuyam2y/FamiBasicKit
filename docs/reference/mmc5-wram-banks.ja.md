# MMC5 の WRAM バンク番号は決め打ちできません

*ビルドを改造する人、または MMC5 で 8KB を超える WRAM を使う人のための文書です。
ここを誤ると、エラーが出ないままメモリが壊れます。*

[English](mmc5-wram-banks.md)

MMC5 では、同じバンク番号でも基板や実装によって指す先が変わります。8KB を超える WRAM を
使う場合は必ず問題になります。

## 何が起きるか

MMC5 では、`$6000-$7FFF` に見える WRAM を `$5113` で、`$8000-$9FFF` に見える WRAM を
`$5114`（bit 7 を 0 にした状態）で選びます。NESdev wiki は、このレジスタのビット配置を
`RAAA AaAA` と記載しています。

問題は bit 2（`a`）です。このビットは「PRG-ROM の A15」と「どちらの WRAM チップを
選ぶか」を兼ねています。そのため、基板に載っている SRAM の数によって同じ番号が別の場所を
指します。

| | `$5114 = $01` | `$5114 = $04` |
|---|---|---|
| 実 ETROM（16KB＝8KB × 2）／EverDrive N8 PRO | チップ 0 のまま（`$6000-$7FFF` のミラー） | チップ 1（独立した 8KB）✅ |
| MiSTer の NES コア | ブロック 1 ✅ | ブロック 4（独立しているが 32KB の `.sav` の範囲外） |
| 実 EWROM（32KB・1 チップ） | 2 つめの 8KB ✅ | open bus |
| チップ 0 に 32KB の SRAM を載せた ETROM の基板（2026-09-04 に実測） | チップ 0 の 2 つめの 8KB ✅（電池側） | チップ 1（独立した 8KB・電池なし） |

MiSTer が単純な連番になっているのは、NES コアの `MMC5.sv` が
`{prgsel[2], prgsel[1:0]}` を連結しているだけだからです。市販の MMC5 ゲームでこの経路
（8KB の SRAM 2 枚）を使うものはないため、実装が対応していなくても表面化しません。

## なぜ問題になるか

ミラーになっていてもエラーが出ないためです。

`$8000-$9FFF` が `$6000-$7FFF` のミラーになっている環境でも、BASIC は 16KB あるものとして
動作し、`16374 BYTES FREE` と表示します。プログラムが 8KB を超えるまでは正常に動作し、
超えた時点から上半分が下半分を上書きします。

## 対処方法

決め打ちをやめ、起動時に判定します（`tools/fb-mmc5-16k.py` の `emit_probe`）。

1. `$5114` に `$01` を書く
2. `$6000-$7FFF` に置いた目印を読み、壊れているかどうかを確認する
3. 壊れていればミラーなので `$04` に切り替える

初期化コードは 71 バイトから 116 バイトに増えます。

### 実装上の注意

- ホットスタート時は、判定に使う 2 バイトにユーザーのプログラムが入っています。
  必ず復元してください。スタックに退避すると、空いているゼロページを探す必要が
  なくなります
- 検証する側に期待するバンク番号を渡さないでください。渡すと、定数が間違っていた場合に
  検証も同じ方向に間違い、そのまま通ってしまいます。代わりに「実際に独立している番号のうち
  最小のものを選ぶ」「触れたバイトが元に戻る」という規則自体をモデル上で実行します
- 小さい番号を優先してください。MiSTer では `$04` も独立していますが、ブロック 4 以降は
  32KB の `.sav`（ブロック 0-3）の範囲外になり、保存されません

### ⚠️ この方法の限界

WRAM が本当に 8KB しかない環境では、判定しても切り替え先が見つかりません。`$01` と `$04` の
どちらもミラーになるため、16KB にはなりません。それでも BASIC は 16KB あるものとして
動作します。

対応するには、BASIC が持つ「領域の末尾」の定数を RAM 参照に変更する改造が別途必要です。
このプロジェクトでは実装していません。手元の 2 台がどちらも 16KB 以上を持っているためです。
8KB しかない環境を対象にする場合は必要になります。

## 出典

- NESdev wiki [MMC5](https://www.nesdev.org/wiki/MMC5) — `$5113`/`$5114` のビット配置（`RAAA AaAA`）
- 実測は 2 台で実施（MiSTer FPGA の NES コアと EverDrive N8 PRO・2026-08-23）
- 実物の MMC5 カートリッジ（維新の嵐の基板）でも実測（2026-09-04）。`$5113` を 0〜3 にすると 4 つとも別のページが
  読め（チップ 0 は 32KB）、4〜7 は同じ 8KB（チップ 1）。`BACKUP` のあと電源を切っても 16,029 バイトの
  プログラムが戻ったので、判定は `$01` を採っている
