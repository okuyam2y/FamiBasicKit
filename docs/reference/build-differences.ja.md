# ビルドごとの違い

*ビルドを改造する人、または複数のビルドで動かすプログラムを書く人のための文書です。
使うだけなら[使い方](../manual/building.ja.md)を読んでください。*

[English](build-differences.md)

ファミリーベーシックはカートリッジとして出荷された製品です。このリポジトリはそれを
書き換えて複数のビルドを作りますが、ビルドによって動作が異なります。この文書では、
あるビルド向けに書いたプログラムを別のビルドで動かしたときに問題になる違いを整理します。

ビルドは NROM 8KB 版・MMC5 16KB 版・ディスク版の 3 種類です。バージョン（V1.0 /
V2.0A / V2.1A / V3.0）は、どのビルドの元にするかという別の軸です。

## 命令は追加していません

予約語は 1 つも追加していません。どのビルドも、元の ROM が持っていた予約語だけを
受け付けます。
トークン番号も元のままです。

これは意図的な方針です。予約語のトークン番号はファイル形式の一部で、`.sav`、カセット、
ディスクに記録されるバイトそのものです。既存の語の番号を変更したり、他の語が使っている
番号を新しい語に割り当てたりすると、これまでに保存したプログラムの意味が変わります。

使われていない番号に新しい語を追加する分には問題ありません。予約語表は項目ごとに
トークン番号を持っているため、途中に追加しても後続の項目の番号は変わりません。
位置で対応しているのは分岐表のほうで、こちらは途中に項目を挿入すると以降の処理が
すべてずれます。

規則は [token-numbering.ja.md](token-numbering.ja.md) にあります。追加した語の一覧は
現在空です。

変わっているのは、既存の語の動作です。該当するのは 2 語で、どちらもディスク版の
`SAVE` と `LOAD` です。

## ビルドの一覧

| | NROM | MMC5 | Disk BASIC（FDS） | VRC7 |
|---|---|---|---|---|
| マッパー | 0 | 5 | なし（ディスクシステム） | 85 |
| 元の ROM | V3（V1/V2 も可） | V3 | V2.1A または V3 | 未定 |
| プログラム領域 | V3 は `$6000-$7FFF`、V1/V2 は `$7000-$7FFF` | `$6000-$9FFF` | `$6000-$7FFF` | 未定 |
| 領域のサイズ | V3 で 8KB、V1/V2 で 4KB | 16KB | 8KB | 未定 |
| 空き容量の表示 | V3 は 8182、V1 は 4031、V2.1A は 4030 | 16374 | V2.1A から 8126、V3 から 8182 | 未定 |
| `SAVE` / `LOAD` | カセット（変更なし） | カセット（変更なし） | ディスク | カセット（変更なし） |
| `BGGET` / `BGPUT` のバッファ | V3 のみ `$7C00-$7FFF`。V1/V2 に両命令はない | `$9C00-$9FFF` | V3 のみ `$7C00-$7FFF`。V2.1A に両命令はない | 未定 |
| `POKE` で届く追加機能 | なし | CHR バンク、拡張属性、走査線 IRQ、矩形波 2 本と PCM、乗算器 | FDS 音源。CHR が RAM なので実行中に文字の絵を書き換えられる | FM 音源 |
| 状態 | 完成・実機確認済み | 完成・実機確認済み | 完成・実機確認済み | 未着手 |

領域のサイズと空き容量の表示は別の数値です。表示のほうは BASIC が内部で使う分を
差し引いています。

V1 と V2 は領域が `$7000` から始まるため、先頭を移動せずに広げると 4KB が上限になります。
V3 は `$6000` から始まるため 8KB まで届きます。詳細は
[ram-expansion.ja.md](ram-expansion.ja.md) にあります。

### ディスク版の「完成」が指す範囲

`SAVE` と `LOAD` は実機（RAM アダプタと FDSKey）で手入力して確認しました。
保存、一覧の消去、読み込み、`LIST` の順に操作し、プログラムが復元されました。

現在のイメージは一連の操作を実機で通しています（2026-08-25・MiSTer・自動実行）。
起動してバナーが表示され、`SAVE "HWTEST"` を入力し、BIOS のエラー番号が 0 になり、
`LOAD` で復元され、`BG GRAPHIC` に入れることを確認しました。その後 SD カードから
ディスクを回収してバイト単位で検証しています。ファイル数が 3 から 4 になり、
新しいヘッダは `03 03 10 HWTEST`、読み込み先は `$603A`、署名と終端ポインタが
プログラムのサイズと一致し、変化したのは全部で 31 バイトでした。電源を入れ直すと
バナーが表示され、プログラムは復元されておらず、`LOAD` で読み込めました。

一方、ドライブを使って実ディスクへ書き込んだことは一度もありません。ここまでの動作確認は
すべて RAM アダプタ経由です。

この点を書いておくことには意味があります。エラーが出ないことは検証ではありません。
また「実機で確認した」は特定のイメージについての記述です。

PC 側のツールには別の検証方法があります。実機が書いたディスクからプログラムを取り出し、
もう一度書き込むと、ディスクがバイト単位で一致します。出力が妥当に見えるかどうかではなく、
実機と同じバイト列を生成できていることを確認しています。

### 使える予約語の数はバージョンで決まります

V3 の予約語表は 109 項目、V2.1A は 88 項目です（演算子 `XOR`〜`*` の 15 個を含む数。
除くと 94 と 73 になります）。どちらの数え方でも差は同じ 21 語で、V3 が追加している
語は次のとおりです。

`AUTO` `BACKUP` `BGGET` `BGPUT` `BGTOOL` `CAN` `CLICK` `CRASH` `DELETE` `ERL` `ERR`
`ERROR` `FILTER` `FIND` `GAME` `INSTR` `RENUM` `RESUME` `SCREEN` `TR` `VCT`

V2.1A にしかない語はありません。

ディスク版はどちらのバージョンからも作れます。したがって、この 21 語が使えるかどうかは
ディスクかどうかではなく、元にした ROM のバージョンで決まります。

- V2.1A から作った場合は、21 語がいずれも使えません（`GAME` と `BGGET`/`BGPUT` を
  含みます）。これは元の ROM の仕様であり、ディスク版が削除したものではありません
- V3 から作った場合は、`GAME` 以外が使えます。`GAME` はディスク版で無効化しています。
  内蔵プログラムが `$E000-$FFFF` にあり、ディスクではこの領域が BIOS になるためです。
  実行すると `?SN ERROR` になります。`BGGET`/`BGPUT` は使え、バッファは領域の末尾に
  合わせて `$7C00` に移動します

グラフィックエディタはどちらのバージョンにもあります。V2.1A から作ったディスク版は
タイトルメニューを残している
ため `SYSTEM` から `2` を選んで `BG GRAPHIC` に入ります。V3 は `BGTOOL` 命令として
持っており、メニューを経由しません。

### `BGGET`/`BGPUT` のバッファは領域のサイズで移動します

V3 のこの 2 命令は 1KB のバッファを共有しており、その位置はプログラム領域の末尾です。
領域を広げるとバッファも移動します。8KB 版で `$7C00-$7FFF`、16KB 版で `$9C00-$9FFF`、
未改造の V3 では `$6C00` です。

`POKE` や `PEEK` でこの付近を操作する場合は注意が必要です。ビルドごとにアドレスが
異なるため、未改造の ROM のアドレスを拡張したビルドで読むと、自分のプログラムの途中を
読むことになります。

### 整数リテラルの範囲はバージョンで異なります

V3 の整数リテラルは符号付き 16 ビット（`-32768` から `32767`）で、V2 系は `0` から
`65535` です。同じ `PEEK(50976)` が V2.1A では通り、V3 では `?OV` になります。
値ではなくバージョンによる違いです。

`PEEK` と `POKE` が届くアドレスはどちらも同じです。V3 では負の数か `&H` で指定します。

## ディスク版の `SAVE` と `LOAD`

ディスクに保存できるプログラムは 1 本です。もう一度保存すると前のものが置き換わります。
`LOAD` は名前で選ばず、ディスクにあるプログラムを読み込みます。Disk BASIC にはこの
2 命令しかなく、一覧も削除もありません。書式とエラー番号は
[使い方](../manual/disk-basic.ja.md)にあります。

保存ルーチンを追加していますが、空き容量は減っていません。内蔵の会話プログラムの
台詞データの上に配置しているためです。ディスク版ではこの部分が実行されることはありません。
確認には `tools/fb-reach.py` を使っています。分岐表を読む命令から到達できる範囲だけを
たどり、指定したアドレスが実行される可能性があるかどうかを判定するツールです。

この 2 命令のほかに、ディスク版が変更している点は次のとおりです。

| | カートリッジ | ディスク |
|---|---|---|
| 文字の絵 | CHR-ROM | CHR-RAM（ディスクから読み込む） |
| 内蔵プログラム | `$E000` 以降の ROM | なし（この領域が BIOS） |
| 電源投入時 | タイトルメニュー | GAME BASIC へ直接起動（`SYSTEM` でメニューへ移動可能） |

## MMC5 版で `POKE` が届く範囲

16KB 版は `$6000-$9FFF` をすべて RAM にしますが、MMC5 のレジスタは `$5000-$5FFF` に
残ります。どの WRAM バンクがどれに対応するか、なぜ決め打ちできないかは
[mmc5-wram-banks.ja.md](mmc5-wram-banks.ja.md) にあります。

## VRC7 版は作っていません

⚠️ 16KB のフリーエリアと VRC7 の FM 音源は両立しません。FM 音源のレジスタは `$9010` と
`$9030` にあり、16KB 版が RAM にしている `$8000-$9FFF` の内側です。そのため 16KB 版で
`POKE 36880` を実行しても、書き込まれるのは RAM で、音源には届きません。
カートリッジが持てるマッパーは 1 つなので、どちらか一方を選ぶことになります。
