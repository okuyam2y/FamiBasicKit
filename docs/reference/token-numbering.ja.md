# トークン番号 — 命令を追加するときの規則

*命令を追加する人のための文書です。書き換える前に読んでください。ここを誤ると、
これまでに保存したプログラムの意味が、エラーも出さずに変わります。*

[English](token-numbering.md)

## この文書がある理由

BASIC のプログラムはテキストとして保存されません。予約語はそれぞれ 1 バイトになり、
そのバイトが `.sav`、カセット、ディスクに記録されます。

つまり予約語の番号は実装の詳細ではなく、ファイル形式の一部です。2 つのビルドで同じ番号に
別の語を割り当てると、一方で書いたプログラムが他方では別のプログラムとして動作します。
エラーも警告も出ません。

これはこのリポジトリが避けようとしている種類の不具合そのものなので、番号の付け方を
命令を追加する前にここで決めています。

## 構造

ROM には、対応を保つ必要のある表が 2 つあります。

**予約語表**は `<トークン><語>` の並びで、トークンは `$80` から始まり、`$FF` で終わります。
V2 は `$C128-$C2C5`、V3 は `$CCAB-$CEBE` に置かれています。

**分岐表**は処理ルーチンのアドレスの一覧で、トークン番号で位置が決まります。
命令は `トークン - $80`、関数は `トークン - $CA` が添字です。

```
  $80-$C9   命令      分岐表の添字 = トークン - $80
  $CA-$EE   関数      分岐表の添字 = トークン - $CA
  $EF-$FD   演算子    (XOR OR AND NOT <> >= <= = > < + - MOD / *)
  $FF       予約語表の終端
```

既存の語の番号は変更できません。変更すると、これまでに保存したすべてのプログラムが
別のプログラムになります。

どちらの表がこの制約を生んでいるかは間違えやすいので書いておきます。予約語表は項目ごとに
トークン番号を持っているため、途中に `<トークン><語>` を挿入しても後続の項目の番号は
変わりません。代わりに、挿入した項目の番号が既存の項目と重複します。重複を避けるには、
その項目以降を手作業で振り直すことになります。

位置で対応しているのは分岐表のほうです。こちらはアドレスが並んでいるだけで、
`トークン - $80` で参照されます。途中に項目を挿入すると、以降の処理ルーチンが 1 つずつ
ずれ、それぞれのトークンが別のルーチンを実行します。

使用中の番号と空き番号は次のコマンドで確認できます。

```
$ ./tools/fb-basic-to-sav.py --tokens "Family BASIC V3 (Japan).nes"
```

番号は手書きの表からではなく、この出力から読んでください。手書きの写しが原因で、
このリポジトリの V2 の一覧から `SCR$` が抜け落ちたまま残っていたことがあります。

## 規則

1. 任天堂が付けた番号は変更しません。元の ROM にある語の番号は動かしません。

2. 追加は、V2.1A と V3 の両方で空いている範囲に限ります。こうすることで、プログラムが
   このリポジトリのどのビルドでも通用します（NROM 8KB 版、MMC5 16KB 版、ディスク版、
   および今後追加するもの）。

   | | このプロジェクト用に確保 | 個数 |
   |---|---|---|
   | 命令 | `$C1-$C9` | 9 |
   | 関数 | `$E7-$EE` | 8 |

   V2.1A にはこれより広い空き（`$B1-$C9` と `$E2-$EE`）がありますが、V3 は `$B1-$C0` を
   `TR` `FIND` `GAME` `BGTOOL` `AUTO` `DELETE` `RENUM` `FILTER` `CLICK` `SCREEN`
   `BACKUP` `ERROR` `RESUME` `BGPUT` `BGGET` `CAN` に使っています。V2 から作ったビルドで `$B1` に
   命令を追加すると、そのプログラムは V3 から作ったビルドでは `TR` として読まれます。

3. 昇順に追加します。分岐表も同じ順に伸ばさないと添字が合わなくなります。

4. 既存の語で始まる語は追加できません。トークン化の処理は表を上から見て最初に一致した
   ものを採用するため、`$B3` に `FDS` があると `FDSLOAD` には到達しません。`FDS` に一致し、
   `LOAD` が残ります。副命令は引数にしてください（`FDS LOAD`）。

5. 使われなくなった枠の転用は可能ですが、下の表に記録してください。`GAME` はディスク版では
   意味がありません。内蔵プログラムが `$E000` 以降にあり、そこがディスクでは BIOS になる
   ためです。この枠は別の用途に使えます。ただし、同じ番号がビルドによって別の意味になるため、
   規則 1 が防いでいる状態に近づきます。習慣にせず、そのつど記録してください。

6. この文書が一覧の正本です。`tools/fb-basic-to-sav.py` が同じ番号を持っており、
   `--selftest` が渡された ROM のバージョンに合わせて照合します。ここに追加したものは、
   そちらにも追加してください。

## 追加するときの手順

予約語表は現在の位置に空きがないため、追加するには表を移動する必要があります。

1. 空きのある場所へ表をコピーし、項目を追加する。トークン番号の順序は保つ
2. 表を読むコードの参照先を変更する（V3 では `$93E7` `$93EB` `$94E1` `$94E5` の
   4 つのオペランド）
3. 分岐表を、追加するトークンの添字まで伸ばす。1 項目増やすだけでは足りません。
   添字は `トークン - $80`（命令）または `トークン - $CA`（関数）で、この作業の後に表は
   `添字 + 1` 個の項目を持つ必要があります（添字は 0 から始まるため、添字 65 には
   0 から 65 までの 66 項目が必要です）。

   現在の表がそこまで届いていない場合は、間の項目を先に用意します。未割り当ての
   トークンに対して元の ROM が行う処理を指しておきます。用意しないと、インタプリタは
   正しい添字を計算したうえで、そこにあった別の値をアドレスとして実行します。
   エラーは出ません。

   V2.1A では、確保した 2 つの範囲のどちらにもこの隙間が既にあります（サイズは
   `tools/fb-reach.py` の `TABLE_RANGES` から読み取ったもので、手書きではありません）。
   命令の表は 49 項目（`$80-$B0`）なので、トークン `$C1`（添字 65）には 16 個の
   ダミー項目（添字 49-64）と本来の 1 項目で合計 66 項目が必要です。関数の表は
   24 項目（`$CA-$E1`）なので、トークン `$E7`（添字 29）には 5 個のダミー項目
   （添字 24-28）と本来の 1 項目で合計 30 項目が必要です。

   V3 側の分岐表についても、実際に変更する前に同じ確認をしてください。この文書には
   V3 の分岐表のサイズを記録していません
4. 分岐表を読むコードの参照先を変更する（V3 では `$8433` `$8438` `$9B39` `$9B3E`、
   関数は `$A4CF` `$A4D4`）
5. `tools/fb-basic-to-sav.py` と上の一覧に語を追加する
6. `--selftest` は元の ROM と食い違うようになりますが、これは正しい動作です。
   検証対象が未改造のダンプだからです。改造したビルドは `--tokens` で確認してください。

## 特に変更できない番号

`$91` は `DATA` です。`READ` は、コメントを読み飛ばさずにプログラムを 1 バイトずつ
走査して `$91` を探します。そのため、`REM` の中にたまたま `$91` と同じバイトがあると、
それが `DATA` 文として読まれます。日本語キーボードではこのバイトが小さいカタカナの
`ェ` にあたるため、実際にはその形で問題が現れます。

予約語を追加してもこの状況は変わりませんが、`$91` を移動すると悪化します。既存の
すべてのプログラムで `DATA` が見つからなくなるためです。「この番号だけ振り直せないのは
なぜか」という疑問に一度で答えるために記載しています。
