# VRC7 版 — `POKE` で FM 音源を鳴らす

[English](vrc7.md)

コナミの VRC7 は 6 チャンネルの FM 音源を積んだカートリッジです。その音源の窓口が 2 つ、
BASIC が `POKE` で書ける番地にあります。この ビルドは V3 をそのマッパーに載せ替えるだけで、
BASIC の中身は変えません。

**増えるのは音で、メモリではありません。** 入力の領域をそのまま引き継ぎます。先に 8KB 化して
おけば 8KB（[ram-expansion.ja.md](ram-expansion.ja.md) の手順でマッパー 0 のまま広げたときと
同じ）になり、起動画面も `8182 BYTES FREE` です。もとの吸い出しをそのまま渡せば V3 本来の
4KB のままです。VRC7 の RAM の窓は `$6000-$7FFF` しかありません。

⚠️ **16KB 版とは、どちらか一方しか選べません。** FM の窓口 `$9010` と `$9030` は、
16KB 版が RAM にしている `$8000-$9FFF` の内側にあります。カートリッジが持てるマッパーは
1 つなので、「プログラムを 16KB 書ける ROM」と「FM が鳴る ROM」は別々になります。

## 作り方

```sh
./tools/fb-expand-basic-area.py "Family BASIC V3 (Japan).nes" -o "V3 (8KB).nes"
./tools/fb-vrc7.py "V3 (8KB).nes" -o "Family BASIC V3.0 (VRC7).nes"
```

1 行目は省略できます（`fb-vrc7.py` は入力のフリーエリアをそのまま引き継ぎます）。
省略すると V3 のもとの 4KB のままです。

| | |
|---|---|
| 入力 | `Family BASIC V3 (Japan).nes`、MD5 `0cc06af39cb084885c34233b1b93b975` |
| 8KB にしたもの | MD5 `f9339eba89ee5b63de2c4c2cad54b082` |
| VRC7 版（8KB 版から） | MD5 `52094d2cd768e8fee8f839c933bbb485`、73,744 バイト、`8182 BYTES FREE` |
| VRC7 版（もとの吸い出しから） | MD5 `a87904a82b1fc9dbe92d5bef07b43728`、大きさは同じ、V3 本来の 4KB |
| ヘッダ | マッパー 85、**サブマッパー 2（VRC7a）**、PRG 64KB、CHR 8KB、電池つき WRAM は入力の宣言どおり |

**受け付ける入力はこの 2 つだけです**。もとの V3 の吸い出しと、そこから作った 8KB 版。
`fb-vrc7.py` はイメージ全体の SHA-256 を取り（8KB 化が書き換える 5 バイトだけは許しますが、
5 つまとめてでなければ通しません）、ヘッダはもとの V3 と 1 バイトずつ比べます。RAM の宣言は
その 5 バイトが表す領域と一致していなければなりません。それ以外は止まります。V1・V2 はもう 1 つ別の理由でも受け付けません。`GAME` の読み込み
ルーチンが別物だからです。構造の検査が見ていない場所が違っている吸い出しは、
止めなければ壊れたまま忠実に変換されてしまいます。

## V2.1A 版

V2.1A も同じマッパーに載ります。こちらはフリーエリアを広げるところまでこの道具がやります。

```sh
./tools/fb-vrc7.py "Family BASIC (Japan) (Rev 2).nes" -o "V2.1A (VRC7).nes"
./tools/fb-vrc7.py --8k "Family BASIC (Japan) (Rev 2).nes" -o "V2.1A (VRC7 8KB).nes"
```

| | |
|---|---|
| 入力 | `Family BASIC (Japan) (Rev 2).nes`（もとの V2.1A の吸い出し） |
| VRC7 版 | MD5 `06e25583ea5bc45ad89d69b2715f4c67`、`1982 BYTES FREE`（入力のまま） |
| `--8k` をつけたもの | MD5 `17add98da0d118ef4204a6400029312c`、`8126 BYTES FREE`、領域は `$6000-$7FFF` |
| 4KB 版に `--8k` | 同じ MD5。4KB 化が 2 つの定数を 8KB と同じ値にしているため |
| ヘッダ | マッパー 85、サブマッパー 2（VRC7a）、**PRG 32KB**（V3 版は 64KB）、CHR 8KB |

**`--8k` は V2.1A 専用です。** V3 は先に `fb-expand-basic-area.py` で広げます。
V2.1A をここで広げるのは、同じことをするのに 17 バイトの書き換えが要り、
その番地をディスク版が既に割り出しているからです。

### 失うもの — 起動時のデモ

⚠️ **電源を入れると出てくる会話・占いのプログラムが無くなります。** 名前を聞いてきて
返事をする、あのプログラムです。この ビルドでは電源投入からいきなり `GAME BASIC` のメニューになります。

置き場所がそこにしかないためです。VRC7 は初期化コードを `$E000-$FFFF` に置くしかなく、
V2.1A はその 8,192 バイトを 1 バイトも余さず使っています。その中で**他から使われていないのは
デモの領域だけ**で、`$F000-$FFF9` の 4,090 バイトあります。8 バイト書き換えて、
デモのハンドラを BASIC 自身のものへ向け、デモの待ちループを飛ばすと、そこが空きます。

**メニューは残ります。** `1--BASIC` も `2--BG GRAPHIC` も `3--END` も動きます。
キーボード・`PLAY`・カセットのルーチンも同じです。これらは `$80AD` より後で、
そこが自前のハンドラを立てるのでデモのものは使っていません。マッパー 0 のまま 8 バイトだけ
書き換えた ROM で確かめてあり、この ビルドは起動のたびに FCEUX でその ROM と画面を突き合わせています。

⚠️ **`--8k` とセーブデータ。** 広げた領域の並びを `fb-basic-to-sav.py` がまだ書けないので、
V2.1A 用に作った `.sav` は `--8k` の ROM と合いません。キーボードから打ち込む分には
そのまま使えます。フラグをつけなければこの差はありません。

## 音を出す

`POKE &H9010,<レジスタ番号>` でレジスタを選び、`POKE &H9030,<値>` でそこに書きます。
チャンネル 0 で 1 音鳴らすのに要るのは 3 本です。

⚠️ **番地は `&H` で書いてください。10 進では書けません。** V3 の整数リテラルは符号付き
16 ビットなので、`36880` と打った時点で `?OV` になり、行が入りません
（[build-differences.ja.md](build-differences.ja.md)）。実機の V3 で同じ音源を鳴らして
いる牧村版の配布プログラムも `&H9010` を使っています。

| レジスタ | 内容 |
|---|---|
| `48`（`$30`） | 上位 4 ビットが楽器、**下位 4 ビットが音量で、大小が逆**。`0` が最大、`15` が最小。**音が消える値はありません**。止めるときはレジスタ `32` でキーオフします |
| `16`（`$10`） | 音の高さ（周波数の値）の下位 8 ビット |
| `32`（`$20`） | ビット 4 で発音開始、ビット 3-1 がオクターブ、ビット 0 が周波数の 9 ビット目、ビット 5 でサステイン |

チャンネル 1〜5 は、この番号に 1〜5 を足したものです（チャンネル 1 なら `$31`・`$11`・`$21`）。
楽器 1〜15 は音源に内蔵されています（1 ブザーベル、2 ギター、3 ワーリー、4 フルート、
5 クラリネット、6 シンセ、7 トランペット、8 オルガン、9 ベル、10 ビブラフォン、11 ビブラホン、
12 トゥッティ、13 フレットレス、14 シンセベース、15 スイープ）。楽器 0 は `$00-$07` に
自分で音色を書いて使う枠です。

```basic
10 REM VRC7 FM TEST
20 A=&H9010:D=&H9030
30 POKE A,48:POKE D,16
40 FOR N=0 TO 11
50 POKE A,16:POKE D,100+N*12
60 POKE A,32:POKE D,24
70 PRINT "*";
80 FOR T=1 TO 300
90 NEXT
100 POKE A,32:POKE D,8
110 NEXT
120 PRINT:PRINT "FM DONE"
```

30 行が楽器 1 を音量最大で選び、50 行が高さ、60 行がオクターブ 4 での発音開始（`24` = `$18`）、
100 行がビット 4 を落として発音の終了です。

音源は `$9010` に書いた後 6 サイクル、`$9030` に書いた後 42 サイクル待つよう決められています。
**BASIC からは気にしなくてかまいません** — `POKE` 1 回のほうがずっと長くかかります。
マシン語から叩くときだけ必要になります。

## `$8000-$FFFF` への `POKE` が無害でなくなります

マッパー 0 では、ROM の番地に書いても何も起きませんでした。VRC7 版ではその番地が
すべてマッパーのレジスタで、書けばハードウェアに届きます。

| 番地 | `POKE` の数値 | 起きること |
|---|---|---|
| `$8000` / `$8010` | `&H8000` / `&H8010` | `$8000` / `$A000` の ROM バンクが切り替わる（**BASIC 本体そのもの**） |
| `$9000` | `&H9000` | `$C000` のバンクが切り替わる |
| `$A000`-`$D010` | | 文字の絵のバンク 8 本。表示が崩れる |
| `$E000` | `&HE000` | 画面のミラーリング、拡張音源の消音（ビット 6）、**WRAM の書き込み許可（ビット 7）**。ビット 7 を落とすとプログラム領域が読み出し専用になる |
| `$F000` | `&HF000` | 走査線 IRQ |

もとの ROM 自身がそこへ書くことはありません。これは推測ではなく実測で、FCEUX で
起動を通して見ると、書き込みは初期化コードの 18 回だけです。

FCEUX で起動して測った結果と、実機で確かめた結果です。

## ROM の組み立て方

VRC7 は電源投入時に何も決まっていません。切り替え式の PRG バンク 3 本、CHR バンク 8 本、
WRAM の書き込み許可が、すべて不定です。BASIC のリセット処理より先に初期化コードを走らせる
必要があり、その置き場所は `$E000-$FFFF` しかありません（電源投入直後に中身が分かっている
唯一の窓）。ところが、もとの ROM ではそこが埋まっています。内蔵プログラムが `$D400` から
`$FFF9` まで、隙間なく並んでいます。

そこで、内蔵プログラム 1 本につき 8KB バンクを 1 つ与えて `$D000` に置き、`GAME` の読み込み
ルーチンを、コピーの前後で `$C000-$DFFF` のバンクを差し替えるものに作り直しました
（16KB 版の MMC5 でやったのと同じ手です）。こうすると `$E000-$FFF9` にある元のコピーは
読まれなくなり、そこが初期化コードと読み込みルーチンの置き場所になります。

| CPU から見える番地 | 中身 |
|---|---|
| `$6000-$7FFF` | WRAM。8KB 化してあれば全部がフリーエリア。広げていない吸い出しからなら下半分の `$6000-$6FFF` |
| `$8000-$9FFF` | バンク 4 ＝ もとの `$8000-$9FFF`。**`$9010`/`$9030` が FM の窓口** |
| `$A000-$BFFF` | バンク 5 ＝ もとの `$A000-$BFFF`。`GAME` の入口だけ差し替え |
| `$C000-$DFFF` | バンク 6 ＝ もとの `$C000-$DFFF`。タイトルの絵もそのまま |
| `$E000-$FFFF` | バンク 7 ＝ もとの `$E000-$FFFF` ＋ 初期化コード ＋ 読み込みルーチン（固定） |
| バンク 0-3 | 内蔵プログラム 1 本ずつ |

VRC7 には基板が 2 種類あり、レジスタの番地の読み方が違います（A3 を見る版は `$x008`、
A4 を見る版は `$x010`）。初期化コードは、紛らわしい番地には両方の書き方で先に書き、
**どちらの読み方でも同じ意味になる番地を最後に書く**ようにしてあります。書き込みが 5 回
増える代わりに、どちらの基板でも正しく立ち上がります。ただし**音源があるのは A4 の版
（VRC7a・サブマッパー 2、このヘッダが名乗っているほう）だけ**です。A3 の版では
`POKE &H9010` は音を出さず、バンクを切り替えてしまいます。
