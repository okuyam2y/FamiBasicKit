## ディスク版で打つこと — `SAVE` と `LOAD`

書式は元からあるものと同じです。変わったのは**行き先**だけです。

### 1枚に1本しか保存できません

**ディスクに入るプログラムは1本です。もう一度保存すると、前のものが置き換わります。**
**本体からは**、2本持つ方法も、ディスクの中身を一覧する方法も、上書き以外に消す方法も
ありません（Disk BASIC にはこの2語しかありません）。**`LOAD` は名前で選びません** —
そこに在るプログラムを読むだけで、どんな名前を付けていても同じです。

名前を付ける意味はあります（ディスクに書かれ、ディスクを読む道具には見えます）が、
**何かを選ぶためのものではありません**。

### 打ち方

| 打つもの | 行き先 |
|---|---|
| `SAVE "NAME"` / `LOAD "NAME"` | ディスク |
| `SAVE` / `LOAD`（引数なし） | ディスク（名前は `BASIC`） |
| `SAVE "DSK:NAME"` / `LOAD "DSK:NAME"` | ディスク（明示） |
| `SAVE "CAS:NAME"` / `LOAD "CAS:NAME"` | カセット（カートリッジ側のルーチン。**12文字まで** — 下記） |

### 名前の長さ

⚠️ **どれであっても名前は16文字までにしてください。**

**ディスクへ保存するときは教えてくれます** — ディスク側の制限が8文字で、それを超えると
エラー `240` で拒否されるからです。`LOAD` と `CAS:` にはその検査がありません。名前は
**誰かが数える前に写され**、長い名前は写し先の器の外へはみ出します。それで害はありません
（そこを見ている命令が ROM の中に1つも無いためです）。31文字あたりを超えると BASIC が
文字列そのものを受け付けません。**実機で測っています**: 20文字で4バイト、26文字で
10バイトはみ出し、32文字は受け付けられず、どの場合も BASIC は動き続けました。これは素の
ファミリーベーシックの挙動を引き継いだもので、この版が持ち込んだものではありません。
**16文字までにしておけばこの話はまるごと関係ありません。**

その範囲の中で、**ディスクへ `SAVE` するときは8文字まで**です。ディスクのファイルヘッダの
名前欄が8バイトだからです。

間違えやすいので正確に書きます: **8文字目より後ろの空白は無視され、空白でない9文字目が
あると拒否されます**（エラー `240`）。ヘッダは短い名前を空白で8文字に埋めるので、
`SAVE "ABCDEFGH   "` は `SAVE "ABCDEFGH"` と同じ名前で、どちらも通ります。
`SAVE "ABCDEFGH X"` は9文字なので、黙って短くするのではなく拒否します。**名前の中の空白は
残ります** — `SAVE "A B"` は `A B` という名前で保存します。

**9文字目がエラーになるのは「ディスクへの保存」だけ**です。`LOAD` は名前を見ません。

**`CAS:` は12文字までで、16文字ではありません。** カセット側のルーチンに渡す前に
`CAS:` のタグを前から削り落とす必要があり、その処理が12バイトだけ写して残りを空白で
埋めます。∴ **カートリッジ自身は受け付ける13〜16文字の名前が、ここでは切り詰められます**。
これはカセットの制限ではなく、この版の `CAS:` の扱いの制限です。

⚠️ **`CAS:` は未検証です。** 手元のエミュレータにデータレコーダが無いので、
カセット側は**受け渡しの手前までしか確かめていません**。カートリッジの習慣を
ディスクに持ち込むときに古い習慣を捨てずに済むように用意してあるもので、
**誰かが動くのを見たわけではありません**。

### 保存や読み込みが失敗したとき

画面には `?TP ERROR` と出ます。カセットのエラーを借りています（専用のエラー語を足すには
BASIC のエラー表を引っ越す必要があるため）。**本当の理由は数字で、自分で読みます:**

```
PRINT PEEK(50976)
```

| | |
|---|---|
| `0` | 直前の転送は通った |
| `3` | ディスクが書き込み禁止 |
| `41` | ディスクが満杯 |
| `240` | 空白でない9文字目がある（末尾の空白は無視される） |
| `241` | `LOAD` がディスクにプログラムを見つけられなかった |
| `255` | まだ一度も走っていない |

⚠️ **V3 のディスクでは `PEEK(50976)` はオーバーフローします。** V3 の整数リテラルは
符号付き16ビットなので、`PRINT PEEK(-14560)` と打ってください（同じ番地です）。
V2.1A はどちらでも通ります。

### 電源を入れ直してもプログラムは戻りません

ディスクは**何も保存していないときとまったく同じ**に立ち上がります（空きメモリの
表示も出ます）。プログラムは `LOAD` と打ったときに戻ります。

2026-08-24 まではこれが逆でした。当時使っていた方のために理由を書いておくと、
**勝手に復元する経路は `8126 BYTES FREE` の印字を飛び越します**。∴ 一度保存すると
そのディスクでは二度と空き容量が表示されず、何を打っても戻せませんでした。
空きが知りたいときは、いつでも `PRINT FRE(0)` で取れます。

### ディスク版で変わるもの、ほか

| | カートリッジ | ディスク |
|---|---|---|
| 文字の絵 | CHR-ROM | CHR-RAM（ディスクから読む） |
| 内蔵プログラム | `$E000` 以上の ROM | **無い** — ディスクではそこが BIOS |
| 電源投入時 | タイトルメニュー | GAME BASIC へ直行（`SYSTEM` でメニューへ戻れる） |

**V3 のディスクでは `GAME` が無くなり**、打つと `?SN ERROR` になります（内蔵プログラムの
置き場所が BIOS だからです）。グラフィックエディタはどちらの版にもあり、入口が違います:
V2.1A のディスクは `SYSTEM` → `2` で `BG GRAPHIC`、V3 は `BGTOOL` コマンドです。

## PC からディスクのプログラムを出し入れする

`tools/fb-fds-file.py` が、使用済みのディスクイメージの中身を触ります。∴ プログラムは
打ち込んだディスクの中に閉じ込められません。

```
$ ./tools/fb-fds-file.py disk.fds --list
$ ./tools/fb-fds-file.py disk.fds --extract -o program.bas
$ ./tools/fb-fds-file.py disk.fds --insert program.bas -o new.fds
```

ほかに渡すものはありません。予約語は**ディスクに入っている BASIC** から読みます。
ディスクは自分のインタプリタを積んでいて、実際にプログラムを走らせるのはそれなので、
**その表だけが正しい**からです。

`--insert` は保存プログラムを**置き換えます**。2本目を足すことはしません。渡された
ディスクを上書きすることも拒否します（`-o` が必須）。

**`--insert` は、何ともないディスクを拒否することがあります。** 長いプログラムを短いものに
置き換えると、古い方の尾部がディスクに残ります（意図してそうしています）。`REM` はどんな
バイトでも持てるので、その尾部が**ファイルヘッダとそっくりな形**になっていることがあり、
次に長いプログラムを入れようとすると「数えられていないファイルを潰す」ように見えます。
その尾部と「誰かが隠したファイル」は**同じバイト列**なので、区別する手はありません。
拒否のときは見つけた位置を示します。**それが自分の古いプログラムの中だと分かるなら
`--over-tail`** を付けると上書きします。

### ディスクは3つの形で戻ってくる（自動で見分けます）

| 形 | 面の開始位置 | 書くもの |
|---|---|---|
| 素の `.fds` | 0 | `fb-fds.py`、および **FDSKey**（`.fds` を直接書き換え、元を `.fds.bak` に残す） |
| fwNES の `.fds` | 16（`FDS\x1a` の後ろ） | 世に出回る他の道具 |
| MiSTer の `.sav` | 16（16バイトのゼロの後ろ） | **MiSTer**（ディスクとは別ファイル） |

拡張子を信じず**両方の位置でブロック1の署名を探して**判別します。面の位置を取り違えると、
他人のプログラムの途中をファイルヘッダとして読むことになるためです。

読めなかったバイトは `\xNN` として出し、**その個数を必ず報告します**。
「何か表示された」と「全部理解できた」を混ぜないためです。
