# MMC5 の WRAM バンク番号は決め打ちできない

[English](mmc5-wram-banks.md)

**同じバンク番号を書いても、基板やコアの実装によって別の場所を指します。**
MMC5 で WRAM を 8KB より多く使おうとすると必ず踏みます。

## 何が起きるか

MMC5 で `$6000-$7FFF` に見せる WRAM は `$5113` で、`$8000-$9FFF` に見せる WRAM は
`$5114`（bit7 を 0 にする）で選びます。ここに書くバンク番号のビットの意味が、
NESdev wiki では `RAAA AaAA` と書かれています。

**問題は `a`（bit2）です。これは「PRG-ROM の A15」と「WRAM チップの /CE 0 と 1 の選択」を
兼ねています。** つまり同じ番号でも、基板に SRAM が何枚載っているかで指す先が変わります。

| | `$5114 = $01` | `$5114 = $04` |
|---|---|---|
| **実 ETROM（16KB＝8KB×2 枚）／EverDrive N8 PRO** | チップ0のまま＝**`$6000-$7FFF` のミラー** | チップ1＝別の 8KB ✅ |
| **MiSTer の NES コア** | ブロック1 ✅ | ブロック4。分かれるが `.sav`（32KB＝ブロック0-3）の外へ出る |
| **実 EWROM（32KB＝1 チップ）** | 2枚目の 8KB ✅ | open bus |

MiSTer が線形なのは、NES コアの `MMC5.sv` が `{prgsel[2], prgsel[1:0]}` と素直に並べている
だけだからです。**市販の MMC5 ゲームはこの経路（8KB SRAM 2枚差し）を踏まない**ので、
実装から抜けていても誰も気づきません。

## 何が困るか

一番たちが悪いのは、**ミラーになっても何のエラーも出ない**ことです。

`$8000-$9FFF` が `$6000-$7FFF` のミラーになっている機材でも、BASIC は
「16KB ある」と信じて `16374 BYTES FREE` と表示します。**8KB を超えるまでは正常に動き、
超えた瞬間に静かに壊れます**（書いた内容が下半分を上書きするため）。

## 対処 — 起動時に書いて読み比べる

決め打ちをやめ、**初期化コードの中で実際に試します**（`tools/fb-mmc5-16k.py` の `emit_probe`）。

1. `$5114` に `$01` を書く
2. `$6000-$7FFF` 側に置いた目印が潰れたか読んで見る
3. 潰れていたら**ミラー**と判断して `$04` へ切り替える

初期化コードは 71 → 116 バイトに増えます。

### 実装で気をつけたこと

- **ホットスタートでは、判定に使う 2 バイトに利用者のプログラムが載っています。**
  必ず復元してください。退避先は**スタック**にしました
  （ゼロページの空き番地を推測しないで済ませるため）
- **検算に「期待するバンク番号」を渡さないこと。** 渡すと定数を間違えたときに検算も一緒に
  間違えて空回りします。代わりに「分かれる中で最小の番号を選ぶ」「触ったバイトが元に戻る」を
  モデル上で実行して確かめます
- **番号は小さい方を選びます。** MiSTer では `$04` でも分かれますが、ブロック4以降は
  `.sav`（32KB＝ブロック0-3）の範囲から外れ、保存されなくなります

### ⚠️ この方法の限界

**WRAM が本当に 8KB しか無い機材では、判定が空振りします。**
`$01` も `$04` もミラーになるため、どちらを選んでも 16KB にはなりません。
それでも BASIC は 16KB のつもりで動きます。

面倒を見るには、BASIC 本体の「領域の最後」の定数を RAM 参照へ書き換える改造が別途要ります。
（前提: この道具を作った環境の実機2台はどちらも 16KB 以上あったため、入れていません。
8KB しか無い機材を相手にするなら必要になります）
