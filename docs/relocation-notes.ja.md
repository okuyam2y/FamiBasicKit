# 8KB のコードを別の番地へ動かすときに踏んだ落とし穴

[English](relocation-notes.md)

同じことをやる人向けの記録です。**多重レビューで、実機に載せた ROM の欠陥が2件出ました。**
どちらも生成物は正常に見え、静的な検算を全部通り、普段の操作では再現しませんでした。

## 1. 「塊ごと動かせば中は保たれる」は2つの意味で成り立たない

相対分岐を直さなくてよいのは、**行き先も塊の中にある場合だけ**です。

### 外へ出る相対分岐（3件）

V3 の実 ROM には、塊の末尾付近から外へ出る分岐が3件ありました
（`$9FE1` / `$9FF9` / `$9FFD` が `$A005` / `$A009` を指す）。動かした後、それらは
**まったく別のコード**（MMC5 初期化の先頭・命令の途中）を指していました。

**対処**: 外へ出る分岐の行き先まで**運ぶ範囲を伸ばす**。伸ばすと新しい分岐が範囲に入るので、
**増えなくなるまで繰り返す**。結果、運ぶ範囲は `$8000-$A001` ではなく **`$8000-$A00A`**
になりました（橋は `$F00B-$F00D`）。

∴ **運ぶ範囲は固定ではありません。** `fb-mmc5-16k.py` は範囲を決め打ちにせず、
`fb-relocate.py` が再導出した値と突き合わせます。決め打ちにしていた版では、
本体が伸びたのに番人が見逃して、**初期化コードが本体を上書きしました**。

### 重なり命令（1件）

`BIT abs`（`2C lo hi`）でオペランド2バイトを読み飛ばし、分岐で1バイト先へ入ると
**その2バイトを別の命令として実行する**書き方があります。

V3 では `$9642` の `BIT $9785`（`2C 85 97`）がこれで、`$9643` へ分岐すると同じ2バイトが
`STA $97` として実行されます。**このオペランドは番地であると同時に命令なので、
番地として書き換えてはいけません**（書き換えると `STA $E7` に化け、分岐経路が別の変数を壊します）。

ROM 全体で重なりは16箇所、要注意は1箇所でした。

**手順**: 動かす前に2つ数える。

- **(a) 塊の中から外を指す相対分岐**（行き先が範囲外のもの）
- **(b) オペランドのバイトが、別の命令の先頭でもある参照**

どちらも 0 なら「閉じている」。0 でなければ、範囲を伸ばすか、その参照を書き換え対象から外す。

**なぜ検算をすり抜けるか**: どちらも**参照の値も命令の切れ目も期待どおり**になるからです。

（前提: 可変長命令で、命令の途中から実行を開始できる命令セット — 6502 / x86 など。
固定長・整列必須の ARM64 等では (b) は起きません）

## 2. バイト列の一致は仮説であって意味ではない

バイナリを検索して見つけた並びは、**そう見えるバイト列**であって、
**そのコードが何をしているか**の証拠ではありません。書き換える前に必ず前後を読んでください。

実例: 「領域の終わりと比較していそうな並び」（`LDA #$70 / CMP / BNE`）を3箇所見つけ、
うち1つを書き換えました。逆アセンブルして読み直すと、それは境界判定ではなく
**ROM から領域いっぱいにデータをコピーするループの終了条件**でした。
終わりを伸ばすと**コピー元が ROM の範囲を越えて読み進み**、番地の回り込みで
副作用のあるレジスタ（PPU）に届きうる状態になっていました。

**手順**: 候補を見つける → **その番地から前後を逆アセンブルして読む** →
「何をするコードか」を言葉で書ける状態にしてから初めて書き換える。
**言葉にできないものは書き換えない。**

`tools/fb-disasm.py` はこのために書きました。`RESET` / `NMI` / `IRQ` から再帰下降し、
**ベクタから実際に辿れた命令だけ**を命令として扱います。
辿れなかった区間は「データ」ではなく **「未確認」として報告**します。

## 3. 番地表とデータ表の見分け

`$80xx-$9Fxx` に見える 16bit 値が全部「動かすべき番地」とは限りません。
**表を読んでいる命令の続きで決めます**。

番地表の形（`JMP` の間接参照に流れ込む）:

```
LDA 表,X / STA $19 / LDA 表+1,X / STA $1A / JMP ($0019)
```

V3 で**触ってはいけないデータ表**（値がたまたま `$80xx-$9Fxx` に見えるだけ）:

| 番地 | 中身 |
|---|---|
| `$8013` | 音の周期 |
| `$B37F` | パレット |
| `$B44A` | ファンクションキーの文字列 |
| `$C787` | 16bit の加算値 |

`fb-disasm.py` の `--find-tables` は「中身が全部 ROM 内の番地になっている連続領域」を
**候補として**挙げるだけです。最後は続きの命令を読んで決めます。

## 4. 直した参照の全数（V3 の実測）

| 種類 | 件数 | 見つけ方 |
|---|---|---|
| 絶対番地の `JSR`/`JMP`/データ参照 | 860 | 逆アセンブルした命令のオペランド |
| 相対分岐 | 479 | **直さない**（行き先も一緒に動くよう範囲を伸ばしてある） |
| 番地表の項目 | 4表 | 上記の形 |
| 即値2つで組み立てた番地 | 2 | `LDA #<lo / STA zp / LDA #>hi / STA zp+1` |
| リセット／IRQ ベクタ | 2 | `$FFFC` / `$FFFE` |

この表は根拠の説明用です。**判断に使うのは実行時の出力の方**（`fb-relocate.py` は
実際に直した数を毎回表示します）。

## 5. 検算の書き方

- **検算は「いくつ変わったか」ではなく「狙った場所が変わったか」で書く。**
  差分の個数で書くと、**間違った場所を同じ個数だけ壊しても通ります**
- **検算に「期待する答え」を渡さない。** 渡すと定数を間違えたときに検算も一緒に間違えて
  空回りします（→ [mmc5-wram-banks.md](mmc5-wram-banks.ja.md) のバンク番号判定）
- **入力を固定する。** `fb-relocate.py` は入力が素の V3 でなければ止まります
  （PRG+CHR の SHA-256・3本のベクタ・未定義オペコードの位置・断片の入口）
- **「動いた」ではなく「素の ROM と同じ画面になる」で確かめる。**
  引っ越しの欠陥は、めったに通らない経路だけが静かに壊れる形で出ます
