# BASIC プログラムの格納形式と `.sav` の作り方

[English](sav-format.md)

`tools/fb-basic-to-sav.py` が実装している内容の説明です。
**ROM 内蔵プログラム4本（387 行・8,999 バイト）を復号 → 再変換して1バイトも違わない**
ことを検定に使っています（`--selftest`）。

## 版によって配置が違う

| | V1.0 / V2.0A / V2.1A | V3.0 |
|---|---|---|
| 領域の先頭 | `$7000` | `$6000` |
| プログラム本体 | `$703E`（オフセット `0x103E`） | `$6006`（オフセット `0x0006`） |
| 起動シグネチャ | `$703A`=`$5A` / **`$703B`=`$33`** | `$6001`=`$4C` |
| プログラム終端 | `$703C/$703D` | `$6002/$6003` |
| 領域の最後 | `$77FF`（拡張版は `$7FFF`） | `$6FFF`（拡張版は `$7FFF`） |

⚠️ **シグネチャと終端の両方が要ります。** シグネチャだけ入れても
「カセットにデータが残っている」表示までは出ますが、終端が無いと空とみなされて
`LIST` に何も出ません。

### V2 系の復元経路（`$80FB` から）

```
80D7  LDA #$5A / STA $703A     ; 保存側
80DC  LDA #$33 / STA $703B
80E3  LDA $07  / STA $703C     ; プログラム終端（下位）
80E8  LDA $08  / STA $703D     ; 　　　　　　（上位）

80FB  LDA $703A / CMP #$5A     ; 復元側（タイトルでキーを1つ押した後に通る）
8102  LDA $703B / CMP #$33
8109  LDA $703C → $07 / LDA $703D → $08
8113  LDA #$3E / LDA #$70 → $05/$06   ; 領域の先頭 $703E
```

⚠️ `$CF5B` にある `CMP #$CC` は**別経路**です。ここを見て「シグネチャは `$CC`」と
読み違えると、`LIST` が空になる現象で延々と詰まります。

### V3 のヘッダ（`$812B` の判定）

| 番地 | `.sav` オフセット | 意味 |
|---|---|---|
| `$6001` | `0x0001` | **シグネチャ `$4C`**。違うとプログラムを捨てる（`$812E` の `CMP #$4C`） |
| `$6002`/`$6003` | `0x0002` | **プログラム終端の番地**（終端の `00` の次） |
| `$6004` | `0x0004` | 起動時にゼロページ `$7C` へ入る（用途未調査。`$00` で動く） |
| `$6006` | `0x0006` | **プログラム本体の先頭**（`$05/$06` に `$6006` が入る） |

## 行の格納形式

```
1行 = [長さ 1B（自分自身を含む）][行番号 2B LE][本体...][00]
本体 = トークン（$80以上） / 生ASCII / 数値 / 文字列（引用符ごと生）
最終行の後ろに 00 を1つ。終端ポインタはその次のバイトを指す
```

**終端ポインタより後ろは、何も決まっていません。** `.sav` は固定長の RAM 像なので
たいていはプログラムの後ろにバイトが残りますが、BASIC はそこを読みません（どこで終わるかは
終端ポインタが決めます）。「たいてい」であって「必ず」ではありません — プログラムが領域を
ちょうど埋めることはあり、そのときは終端バイトの後ろに何も残りません。どちらも特別な
状態ではありません。実機が書いた `.sav` ではそこが `0x20` でしたが、
`fb-basic-to-sav.py` は新規なら 0 で埋め、`--base` なら元のまま残します。この頁は
`0x20` 埋めを形式の一部として規定していましたが、ここのどの道具もそれを作りませんし、
必要とするものもありません。

### 数値の入れ方は3通り＋1

全部 `$12` だと思っていた版では、`GOTO`/`GOSUB` を含むプログラムが必ず `?SN ERROR` に
なりました。

| 形 | バイト | 何 |
|---|---|---|
| 小さい整数 | `$01`-`$0A` | **0-9**（値 + 1。`$00` が行の終端なのでずらしてある） |
| 整数 | `$12 lo hi` | **10 以上** |
| 16進 | `$11 lo hi` | `&Hxxxx` と書いたもの |
| 行番号 | `$0B lo hi` | `GOTO`/`GOSUB`/`THEN`/`RESUME`/`RESTORE` の後ろと、その続きの `,` |

⚠️ **1桁の短縮形は V3 だけ**です（V2 系は 0-9 も `$12 lo hi`）。

⚠️ **`REM` と `DATA` の後ろは行末まで生のまま**入ります（トークン化も数値化もされません）。
`DATA 11,22` を数値トークンで入れると `READ` が `?TM ERROR` になります。

例: `10 POKE 24576,65` → `0d 0a 00 9e 20 12 00 60 2c 12 41 00 00`

**文字列は引用符ごと生の ASCII**です。予約語だけが1バイトのトークンに畳まれます。
`,` `(` `)` は生の ASCII のままです。

### トークン表は版で違う

**V3 は 109 語**（`$CCAB-$CEBE`）、V2 系は 88 語（`$C128-$C2C5`）。
どちらも表を終わらせる `$FF` を含む範囲で、ROM から実測した値です。この頁は
`$C120-$C2BF`・`$CCAB-$CEBD` と書いていて、同じ表について道具の言うことと
食い違っていました。番地を頁ではなく ROM から取る理由がこれで、
`fb-basic-to-sav.py` はそうしています。
V3 で増えるのは `TR` `FIND` `GAME` `BGTOOL` `AUTO` `DELETE` `RENUM` `FILTER` `CLICK`
`SCREEN` `BACKUP` `ERROR` `RESUME` `BGPUT` `BGGET` `CAN` `INSTR` `CRASH` `ERR`
`ERL` `VCT` の 21 語です。

以前この頁は 87 語・22 語と書き、`SCR$` を V3 の追加語に数えていました。**V2.1A にも
`SCR$` は在り、番号も V3 と同じ `$E1` です**（両方の ROM から数えました）。
手書きの表から落ちたのと同じ語で、道具が表を ROM から読む理由そのものです。

⚠️ **V3 に V2 の表を使うと、増えた語が1文字ずつの ASCII に化けます。**
表の形式は「トークン値（bit7 立ち）→ 語の ASCII」の繰り返しなので、ROM から読み直せます。

⚠️ **`TAB` / `SPC` / `COLOR` は予約語ですが命令としては実装されていません**
（V3 マニュアル「拡張用予約語のため、変数名には使えません」）。実機でも `?SN ERROR` になります。

## 検定

```bash
./tools/fb-basic-to-sav.py --selftest "Family BASIC V3 (Japan).nes"
```

ROM の内蔵プログラム4本を復号 → 再変換して**1バイトも違わない**ことを求めます。
予約語の表も ROM から読み直して突き合わせます。**正解を自分の理解に置かない**ための作りです
（逃がした＝解釈できなかったバイトは 2.2%）。

## 使い方

```bash
./fb-basic-to-sav.py prog.bas -o out.sav                    # V2.1A（既定）
./fb-basic-to-sav.py prog.bas -o out.sav -V v3 --expanded   # V3 の 8KB 版
./fb-basic-to-sav.py prog.bas -o out.sav -V v3 --16k        # V3 の 16KB 版（32KB の .sav）
```

`--expanded` は領域を広げた ROM 用（最後が `$7FFF`）。`--16k` はサイズが自動で 32768 になり、
`-V v2` との併用や `--size 8192` の明示はエラーになります。
シグネチャと終端ポインタはツールが自動で入れます。

## おまけ

**`POKE`（`$9E`）/ `PEEK`（`$CF`）/ `CALL`（`$AD`）が使えます。**
拡張前でも、BASIC が使っていない WRAM はデータ置き場として `POKE`/`PEEK` で触れます。

```basic
POKE 24576,65 : PRINT PEEK(24576)   ' $6000 → 65 が返る
```
