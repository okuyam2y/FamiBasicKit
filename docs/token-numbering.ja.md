# トークン番号 — BASIC の命令を足すときの決まり

[English](token-numbering.md)

## この文書がある理由

BASIC のプログラムは文字列では保存されません。予約語は**1バイトの番号**になり、
その番号がそのまま `.sav` にも、カセットにも、ディスクにも入ります。

∴ 命令の番号は**実装の都合ではなくファイル形式**です。同じ番号を版によって別の命令に割り当てると、
片方で書いたプログラムが、もう片方では**エラーも警告も出さずに別のプログラムとして動きます**。
このリポジトリが避けようとしているのは、まさにこの壊れ方です。
だから番号は、命令を1つも足す前に、ここで一度だけ決めます。

## 構造

ROM には歩調を合わせる必要のある表が2つあります。

**予約語表**は `<番号><綴り>` の並びで、番号は `$80` から、`$FF` で終端。
V2 は `$C128-$C2C5`、V3 は `$CCAB-$CEBE` に置いています。

**分岐表**は処理ルーチンの番地の並びで、**番号で引かれます**。
命令は `番号 − $80`、関数は `番号 − $CA` が添字です。

```
  $80-$C9   命令    分岐表の添字 = 番号 − $80
  $CA-$EE   関数    分岐表の添字 = 番号 − $CA
  $EF-$FD   演算子  (XOR OR AND NOT <> >= <= = > < + - MOD / *)
  $FF       予約語表の終端
```

∴ **既にある語の番号を変えてはいけません。**
変えると過去に保存した全プログラムが別のプログラムになります。

**どちらの表がこれを強制しているのか**に注意してください。2つは挙動が違い、取り違えやすい:
予約語表は項目ごとに番号のバイトを明示して持っているので、`<番号><綴り>` の組を途中へ
入れても、**それ以降の項目の番号はずれません**（書いてあるとおりのままです）。代わりに
起きるのは、他の項目が既に名乗っている番号を新しい組が名乗ることで、手で番号を振り直さない
限り衝突します。**位置で引かれるのは分岐表のほう**です。あちらは番地が並んでいるだけで
`番号 − $80` が添字なので、途中に項目を入れると**それ以降のハンドラが番号1つ分ずれ**、
その番号のトークンが全部間違ったルーチンを実行します。

ある ROM が何を使っていて何が空いているかは、こう出します。

```
$ ./tools/fb-basic-to-sav.py --tokens "Family BASIC V3 (Japan).nes"
```

**手で書いた表からではなく、これで読んでください。** 手で写した表がズレる例は既にあって、
このリポジトリの V2 の一覧から `SCR$` が抜けたまま気づかれずにいました。

## 決まり

1. **任天堂の番号は凍結。** 素の ROM にある語は1つも動かしません。

2. **追加は V2.1A と V3 の両方で空いている範囲に置く。** こうすれば、
   ここで作る全部の版（NROM 8KB / MMC5 16KB / FDS / 以降）でプログラムが持ち運べます。

   | | このプロジェクトの予約 | 個数 |
   |---|---|---|
   | 命令 | `$C1-$C9` | 9 |
   | 関数 | `$E7-$EE` | 8 |

   V2.1A 単体ならもっと空いています（`$B1-$C9` と `$E2-$EE`）。しかし V3 は `$B1-$C0` を
   `TR` `FIND` `GAME` `BGTOOL` `AUTO` `DELETE` `RENUM` `FILTER` `CLICK` `SCREEN`
   `BACKUP` `ERROR` `RESUME` `BGPUT` `BGGET` `CAN` で使っています。
   V2 の版で `$B1` に新しい命令を置くと、**そのプログラムは V3 の版で `TR` として読まれます**。

3. **昇順に追記する。** 分岐表も同じ順で伸ばさないと添字が合わなくなります。

4. **既存の語で始まる新語は作れない。** トークナイザは表を上から見て最初に一致した語を採るので、
   `$B3` に `FDS` があると、後ろに置いた `FDSLOAD` には永久に届きません
   （`FDS` が先に一致して `LOAD` が残る）。副命令は**別の語ではなく引数**にしてください
   （`FDS LOAD` の形）。

5. **死んでいる枠の転用は可。ただし下に記録する。** ディスク版では `GAME` は意味を持ちません
   （内蔵プログラムは `$E000` 以降にあり、そこはディスクでは BIOS だからです）。
   ∴ その枠は別の語に使えます。代償は**その番号だけ版によって意味が変わる**ことで、
   これは決まり1が防いでいるものそのものです。習慣にせず、決定として記録します。

6. **この文書が正本。** `tools/fb-basic-to-sav.py` が同じ番号を持っていて、
   `--selftest` は渡された ROM の版に合わせて一覧を照合します。
   ここに足したら、あちらにも足してください。

## 実際に足すときの手順

予約語表は今いる場所で満杯なので、語を足すには表ごと引っ越します。

1. 余裕のある場所へ表を複製し、番号順を保ったまま項目を追加する
2. 表を読むコードの参照先を書き換える（V3 は `$93E7` `$93EB` `$94E1` `$94E5` の4箇所）
3. **分岐表は「1項目」ではなく、新しいトークンの index まで伸ばす。** index は
   `token - $80`（コマンド）または `token - $CA`（関数）で、この手順のあとに表は
   `index + 1` 項目持っていなければならない（index は0始まりなので、index 65 には
   0-65の66項目が要る。65項目ではない）。今の表がそこまで届いていないなら、間の項目を
   先に埋める必要がある（このROMが未割り当てトークンに対してすでにやっていることを指す
   ようにする）——埋めないと、インタプリタは正しい index を計算してそこに偶然あるものを
   黙って実行してしまう。**V2.1A ではこの隙間が両方の予約範囲にすでにある**（数字は
   手書きではなく `tools/fb-reach.py` の `TABLE_RANGES` から読んだもの）: コマンド表は
   49項目（`$80-$B0`）なので、トークン `$C1`（index 65）には16項目のプレースホルダー
   （index 49-64）＋本体1項目＝合計66項目が要る。関数表は24項目（`$CA-$E1`）なので、
   トークン `$E7`（index 29）には5項目のプレースホルダー（index 24-28）＋本体1項目＝
   合計30項目が要る。V3 でどの表を触るにせよ、「1項目」を
   前提にする前に同じ確認をすること——このファイルには V3 の分岐表のサイズをまだ
   書いていない
4. **分岐表**を読むコードの参照先も書き換える
   （V3 は `$8433` `$8438` `$9B39` `$9B3E`、関数は `$A4CF` `$A4D4`）
5. `tools/fb-basic-to-sav.py` と上の割り当て表に語を足す
6. `--selftest` は素の ROM と食い違うようになりますが、**それが正しい**
   （あれは素のダンプを見る検定です）。改造した版は `--tokens` で確認してください

## 1つだけ、他より強く凍結されている番号

`$91` は `DATA` です。`READ` はデータを探すとき、**プログラムを1バイトずつ走査して `$91` を探し、
コメントを飛ばしません**。∴ `REM` の中にたまたま `$91` と同じバイトがあると、
そこが `DATA` 文として読まれます。日本語キーボードではそのバイトが小書きの `ェ` で、
実際にはその形で踏みます。

命令を足してもこの罠は悪化しません。しかし `$91` を動かすと**決定的に悪化します** —
既存の全プログラムの `DATA` が見つからなくなります。
「なぜこの番号だけ動かせないのか」を一度で答えられるように、ここに書いておきます。
