# 版ごとに何が変わり、何は変わらないか

[English](build-differences.md)

ファミリーベーシックはカートリッジとして出荷されたものです。このリポジトリはそれを
書き換えて何種類かの版を作りますが、**版によって振る舞いが違います**。この文書は
その違いの一覧です。ある版で書いたプログラムと、ある版で身についた癖が、別の版で
黙って壊れないようにするためのものです。

## どの版もコマンドを増やしていません

**追加した命令語は1つもありません。** どの版も、元の ROM が答えていた予約語だけに答え、
その番号も昔のままです。

これは意図してそうしています。**予約語の番号はファイル形式そのもの**で、`.sav` にも
カセットにもディスクにも、その1バイトが入ります。何を失うかは正確に書く価値があります。
**既存の語の番号を変える／新しい語に他の語が使っている番号を与える**と、過去に保存した
全プログラムが黙って別のプログラムになります。一方、**どこも使っていない番号に新しい語を
置く分には、過去の保存データは変わりません** — 予約語表は項目ごとにトークンのバイトを
持っているので、後ろの項目の番号はずれないからです（`docs/token-numbering.md`）。位置で
引くのは**分岐表**の方で、その途中に足すと以降の処理が1つずつずれます（レビューで判明）。
これを守るための規則は `docs/token-numbering.md` にあり、追加の登録簿は空のままです。

代わりに変わったのは、**既存の語の意味**です。該当するのは2語だけで、どちらもディスク版の
`SAVE` と `LOAD` です。

## 版の一覧

| プログラム領域 | V3 は `$6000-$7FFF`、V1/V2 は **`$7000-$7FFF`** | `$6000-$9FFF` | `$6000-$7FFF` | 未定 |
| 領域の大きさ | V3 で 8KB、**V1/V2 で 4KB** | 16KB | 8KB | 未定 |
| 何も読んでいないときの `BYTES FREE` | V3 `8182`、V1 `4031`、V2.1A `4030` | `16374` | V2.1A から `8126`、V3 から `8182` | 未定 |
| `SAVE` / `LOAD` | カセットのまま | カセットのまま | **ディスクへ**（下記） | カセットのまま |

領域の大きさと `BYTES FREE` の表示は**別の数**なので、表でも分けてあります（表示は
BASIC が自分用に取る分を引いた値）。実測値は `README.md` から、ディスク版のものは
`fb-fds.py` が報告する値です。

### ディスク版の「完成」が指す範囲

`SAVE` と `LOAD` は、本物のファミコン（RAM アダプター＋FDSKey）で打鍵して確認しました
（保存 → 一覧を消す → 読み込み → `LIST` でプログラムが戻る）。

**今のイメージは、一連の流れを実機で通してあります**（2026-08-25・MiSTer・人手ゼロ）:
起動してバナーが出る → 打鍵で `SAVE "HWTEST"` → BIOS のエラー番号が 0 → `LOAD` で戻る →
`BG GRAPHIC` → SD カードからディスクを回収してバイトで検める（ファイル数が 3→4、
新しい見出しは `03 03 10 HWTEST`、`$603A` に読み込み、署名と終端ポインタが大きさと合う、
**変化したのは全部で31バイト**）→ 電源を入れ直すとバナーが出て、プログラムは戻っておらず、
`LOAD` と打てば戻る。

**まだ一度もしていないのは、ドライブ本体を使った実ディスクへの書き込み**です。
ここまでの往復はどれもディスクのモーターを回していません。ドライブ本体を使った実ディスクへの
書き込みも同様で、上の往復はディスクのモーターを回していません。

表が「完成」に見えることより、ここを書いておくことの方が大事です。「エラーが出ていない」
は検証ではなく、「実機確認済み」は**特定のイメージについての主張**で、今のイメージは
それではありません（レビューで判明）。

**V1 と V2 は領域が `$7000` から始まる**ので、始点を動かさずに広げると 4KB で頭打ちに
なります。V3 は `$6000` から始まるので 8KB まで届きます。詳細は `docs/ram-expansion.ja.md`。

### その前に、答える語の数が違います

V3 の予約語表は 109 項目、**V2.1A は 88 項目**です（演算子 `XOR`〜`*` の15個を含めた表の
総数。除くと 94 と 73）。どちらの数え方でも差は同じ 21 語で、V3 が足しているのは
`AUTO` `BACKUP` `BGGET` `BGPUT` `BGTOOL` `CAN` `CLICK` `CRASH` `DELETE` `ERL` `ERR`
`ERROR` `FILTER` `FIND` `GAME` `INSTR` `RENUM` `RESUME` `SCREEN` `TR` `VCT` で、
V2.1A にしか無い語はありません。

**ディスク版はどちらの版からも組めます**。∴ この21語が使えるかどうかは、
ディスクかどうかではなく**組んだ元の ROM** で決まります:

- **V2.1A から組んだ場合** — **21語はどれも使えません**（`GAME`・`BGGET`/`BGPUT` を含む）。
  これは**土台の ROM の性質**であって、ディスク版が取り上げたわけではありません
- **V3 から組んだ場合** — `GAME` 以外は使えます。`GAME` はディスク版が潰しています
  （内蔵プログラムは `$E000-$FFFF` にあり、ディスクではそこが BIOS のため）。
  打つと `?SN ERROR` になります。`BGGET`/`BGPUT` は使えて、
  バッファは領域の上端と一緒に `$7C00` へ移ります

グラフィックエディタはどちらにもありますが、入り方が違います。V2.1A 版はタイトルメニューを
残しているので `SYSTEM` → `2` で `BG GRAPHIC` に入り、V3 は `BGTOOL` 命令として持っていて
メニューを必要としません。

### `BGGET`/`BGPUT` のバッファは領域の上端について動きます

V3 のこの2語は 1KB のバッファを共有していて、それが**プログラム領域の上端に貼り付いて
います**。∴ 領域を広げると**バッファも動きます** — 8KB 版で `$7C00-$7FFF`、
16KB 版で `$9C00-$9FFF`。素の V3 は `$6C00` です。

`POKE`/`PEEK` でこの辺を触るなら重要です。**版ごとに番地が違う**ので、素の番地を
広げた版で読むと、**自分のプログラムの途中**を読むことになります。

## Disk BASIC の `SAVE` と `LOAD`

### 1枚に1本しか保存できません

**ディスクに入るプログラムは1本です。もう一度保存すると、前のものが置き換わります。**
**本体からは**、2本持つ方法も、ディスクの中身を一覧する方法も、上書き以外に消す方法も
ありません（Disk BASIC にはこの2語しかありません）。PC からなら後述の
`fb-fds-file.py --list` でディスクイメージの中身は見えます — 制限は本体側のもので、
ディスクの形式のものではありません。**`LOAD` は名前で選びません** — そこに在るプログラムを読むだけで、
どんな名前を付けていても同じです。

名前を付ける意味はあります（ディスクに書かれ、ディスクを読む道具には見えます）が、
**何かを選ぶためのものではありません**。

### 打ち方

| 打つもの | 行き先 |
|---|---|
| `SAVE "NAME"` / `LOAD "NAME"` | ディスク |
| `SAVE` / `LOAD`（引数なし） | ディスク（名前は `BASIC`） |
| `SAVE "DSK:NAME"` / `LOAD "DSK:NAME"` | ディスク（明示） |
| `SAVE "CAS:NAME"` / `LOAD "CAS:NAME"` | カセット（カートリッジ側のルーチン。**12文字まで** — 下記） |

⚠️ **どれであっても名前は16文字までにしてください。**

**ディスクへ保存するときは教えてくれます** — ディスク側の制限が8文字で、それを超えると
エラー `240` で拒否されるからです（後述）。書いておく価値があるのは**そこへ至る途中**の
話と、その検査を持たない `LOAD` と `CAS:` の話です。名前は**誰かが数える前に写され**、
長い名前は写し先の器の外へはみ出します。それで害は無いのですが、理由が珍しいので
書いておきます。

BASIC は名前を **`$0580` からの16バイトの器**に写し、その次の `$0590` に `$00` を置きます。
器を埋めるルーチンも、名前を比べるルーチンも、この版が名前を取り出す所も、**きっかり
16バイト**のつもりで書かれています。ところが**パーサの写しには長さの検査がなく**、
文字列の長さだけ書き続けます。∴ 17文字から31文字あたりまでの名前は `$0590` の先へ
数バイトはみ出します — そして**そこを見ているものは ROM の中に何もありません**。
32KB を通して `$0591` 以降を番地で名指ししている命令は0箇所で、索引で届くのはパーサ自身
だけです。31文字あたりを超えると BASIC が文字列そのものを受け付けず、写しは起きません。

推論ではなく**実機で測りました**: 20文字で4バイト、26文字で10バイトはみ出し、32文字は
受け付けられず、どの場合も BASIC は動き続けました。これは素のファミリーベーシックの挙動で
（改造していないカートリッジのカセット `SAVE` も同じ）、この版は同じパーサを呼ぶことで
引き継いでいます。`SAVE`・`LOAD`・`CAS:` のどれもです。**16文字までにしておけばこの話は
まるごと関係ありません**。上の制限を16文字と書いているのはそのためで、この版の名前検査も
同じ理由で `$0590` で止まります — 通すか拒むかは必ず器の中だけで決まります。

∴ **「9文字目でエラー」は安全のための制限ではありません** — あれはディスクのファイル名の
長さの話で、器の話ではありません。

**ディスクへ `SAVE` するときは**、名前は8文字までで、9文字目があると拒否します
（エラー `240`）。これはディスクのファイルヘッダの名前欄が8バイトだからで、検査は
`SAVE` の側にしかありません。

間違えやすいので正確に書きます: **8文字目より後ろの空白は無視され、空白でない9文字目が
あると拒否されます**。ヘッダは短い名前を空白で8文字に埋めるので、`SAVE "ABCDEFGH   "` は
`SAVE "ABCDEFGH"` と同じ名前で、どちらも通ります。`SAVE "ABCDEFGH X"` は9文字なので、
黙って短くするのではなく拒否します。**名前の中の空白は残ります** — `SAVE "A B"` は
`A B` という名前で保存します（レビューで判明）。`LOAD` は長さを見ませんし、そもそも**名前を使いません**
（ディスクに在る1本を読むだけです）。`CAS:` は名前をカセット側のルーチンに渡します。
∴ **9文字目がエラーになるのは「ディスクへの保存」だけ**です。`LOAD` は無視します。

**`CAS:` は12文字までで、16文字ではありません。** カセット側のルーチンに渡す前に
`CAS:` のタグを前から削り落とす必要があり、その処理が12バイトだけ写して残りを空白で
埋めます。∴ **カートリッジ自身は受け付ける13〜16文字の名前が、ここでは切り詰められます**。
これはカセットの制限ではなく、この版の `CAS:` の扱いの制限です（レビューで判明）。
そもそもカセット経路はこちらで一度も動かして見ていません。

⚠️ **`CAS:` は未検証です。** 手元のエミュレータにデータレコーダが無いので、
カセット側は**受け渡しの手前までしか確かめていません**。カートリッジの習慣を
ディスクに持ち込むときに古い習慣を捨てずに済むように用意してあるもので、
**誰かが動くのを見たわけではありません**。

### 電源を入れ直してもプログラムは戻りません

ディスクは**何も保存していないときとまったく同じ**に立ち上がります（空きメモリの
表示も出ます）。プログラムは `LOAD` と打ったときに戻ります。

2026-08-24 まではこれが逆でした。当時使っていた方のために理由を書いておくと、
**勝手に復元する経路は `8126 BYTES FREE` の印字を飛び越します**。∴ 一度保存すると
そのディスクでは二度と空き容量が表示されず、何を打っても戻せませんでした。
空きが知りたいときは、いつでも `PRINT FRE(0)` で取れます。

### 保存や読み込みが失敗したとき

画面には `?TP ERROR` と出ます。カセットのエラーを借りています（専用のエラー語を足すには
BASIC のエラー表を引っ越す必要があるため）。**本当の理由は数字で、自分で読みます:**

```
PRINT PEEK(50976)
```

| | |
|---|---|
| `0` | 直前の転送は通った |
| `3` | ディスクが書き込み禁止 |
| `41` | ディスクが満杯 |
| `240` | 空白でない9文字目がある（末尾の空白は無視される） |
| `241` | `LOAD` がディスクにプログラムを見つけられなかった |
| `255` | まだ一度も走っていない |

### ディスク版で変わるもの、ほか

| | カートリッジ | ディスク |
|---|---|---|
| 文字の絵 | CHR-ROM | CHR-RAM（ディスクから読む） |
| 内蔵プログラム | `$E000` 以上の ROM | **無い** — ディスクではそこが BIOS |
| 電源投入時 | タイトルメニュー | GAME BASIC へ直行（`SYSTEM` でメニューへ戻れる） |

## PC からディスクのプログラムを出し入れする

`tools/fb-fds-file.py` が、使用済みのディスクイメージの中身を触ります。∴ プログラムは
打ち込んだディスクの中に閉じ込められません。

```
$ ./tools/fb-fds-file.py disk.fds --list
$ ./tools/fb-fds-file.py disk.fds --extract -o program.bas
$ ./tools/fb-fds-file.py disk.fds --insert program.bas -o new.fds
```
**`--insert` は、何ともないディスクを拒否することがあります。** 長いプログラムを短いものに
置き換えると、古い方の尾部がディスクに残ります（意図してそうしています）。`REM` はどんな
バイトでも持てるので、その尾部が**ファイルヘッダとそっくりな形**になっていることがあり、
次に長いプログラムを入れようとすると「数えられていないファイルを潰す」ように見えます。
その尾部と「誰かが隠したファイル」は**同じバイト列**なので、区別する手はありません。
拒否のときは見つけた位置を示します。**それが自分の古いプログラムの中だと分かるなら
`--over-tail`** を付けると上書きします。


ほかに渡すものはありません。予約語は**ディスクに入っている BASIC** から読みます。
ディスクは自分のインタプリタを積んでいて、実際にプログラムを走らせるのはそれなので、
**その表だけが正しい**からです。一時は `--rom` で外から渡す作りにしていましたが、
それだと V3 のダンプでトークン化して、この版が知らない語を書けてしまいました。

### ディスクは3つの形で戻ってくる（自動で見分けます）

| 形 | 面の開始位置 | 書くもの |
|---|---|---|
| 素の `.fds` | 0 | `fb-fds.py`、および **FDSKey**（`.fds` を直接書き換え、元を `.fds.bak` に残す） |
| fwNES の `.fds` | 16（`FDS\x1a` の後ろ） | 世に出回る他の道具 |
| MiSTer の `.sav` | 16（16バイトのゼロの後ろ） | **MiSTer**（ディスクとは別ファイル） |

形は3つですが、**位置は2つ**です（面の開始は 0 か 16）。16 を共有する2つを分けるのは
前置きの16バイトで、fwNES は `FDS\x1a` を書き、MiSTer はゼロのままにします。拡張子を
信じず**両方の位置でブロック1の署名を探して**判別します。面の位置を取り違えると、
他人のプログラムの途中をファイルヘッダとして読むことになるためです。

### 1本だけ、置き換え

`--insert` は保存プログラムを**置き換えます**。2本目を足すことはしません（この版は
1枚に1本で、`LOAD` はそこに在るものを読むため）。渡されたディスクを上書きすることも
拒否します（`-o` が必須）。

### 「動いた」の意味

意味があるのは、**本物のファミコンが書いたディスクとの往復**です。プログラムを取り出して
入れ直すと、ディスクが**バイト単位で完全一致**します。「それらしいものが表示された」より
強く、**機械と同じバイトを組めている**ということです。

読めなかったバイトは `\xNN` として出し、**その個数を必ず報告します**。
「何か表示された」と「全部理解できた」を混ぜないためです。

## MMC5 で `POKE` が届くもの

16KB 版は `$6000-$9FFF` を全部 RAM にしますが、MMC5 自身のレジスタは
`$5000-$5FFF` にあるので届きます。どの WRAM バンクがどれかは
`docs/mmc5-wram-banks.ja.md` にあります。

## VRC7 は作っていません

⚠️ **16KB のフリーエリアと VRC7 の FM 音源は両立しません。** FM のレジスタは
`$9010`/`$9030` にあり、そこは 16KB 版が RAM にしている `$8000-$9FFF` の中です。
∴ 16KB 版で `POKE 36880` と書いても、音源ではなく RAM に書きます。
**どちらか一方**で、別々の ROM になります（カートリッジはマッパーを1つしか持てません）。
